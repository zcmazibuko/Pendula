This is one of the most important components of the application.

Create a fully functional **virtual educational rewards banking system**.

It must behave like a professional banking ledger, but it must not be represented as a real financial institution.

Pendula points are educational rewards, not South African rand, deposits, electronic money or legal tender.

Unless a separate, legally reviewed redemption programme is implemented, points must have no cash value.

## 10.1 Learner Accounts

- Unique account number

- Current points balance

- Interest earned
- Transaction history
- Savings goals
- Account opening date
- Account status
- Last transaction date

## 10.2 Double-Entry Ledger

Implement an immutable, auditable ledger with appropriate balancing accounts.

Do not use a simple editable balance field as the source of truth.

Every transaction must have:

- Unique transaction ID
- Transaction type
- Date and time
- Learner account
- Points amount
- Source or destination ledger account
- Reason
- Rule version
- Initiating user
- Approving user, where required
- Linked attendance, assessment or achievement record
- Idempotency key
- Audit metadata

Use atomic database transactions.

Ensure that concurrent actions cannot cause lost updates or double credits.

Any cached balance must reconcile with the authoritative ledger.

# 16. POINT DEDUCTION APPROVAL SYSTEM

This requirement is critical.

**No teacher may deduct points without administrator approval.**

## 16.1 Deduction Workflow

When a teacher requests a deduction:

1. Select the learner.
2. Select the transaction or deduction category.
3. Enter the proposed points amount.
4. Provide a reason.
5. Attach evidence where necessary.
6. Submit the request.
7. Notify administrators.
8. Place the request in the approval queue.
9. Require administrator review.
10. Approve or reject.
11. Record the decision.
12. If approved, post the debit transaction atomically.
13. Notify the relevant teacher.

A pending request must not change the balance.

## 16.2 Security

Teachers cannot approve their own requests.

Rejected requests must not alter balances.

Approved requests must be applied only once.

Require a fresh balance check at posting time.

Prevent unauthorised negative balances.

Do not allow teachers to modify an approved request.

## 16.3 Corrections

If an incorrect credit was issued, do not delete it.

Create an auditable compensating transaction after approval.

Preserve both the original transaction and the correction.

## 16.4 Ethical Reward Governance

Do not encourage punitive deductions for disability-related needs, poverty, illness, protected characteristics or circumstances outside a learner's control.

Create configurable safeguards against unfair deductions.

Allow legitimate disputes and administrator review.
